# FFmpeg WASM core

This directory contains the local FFmpeg WebAssembly core used for remuxing
and merging media. The extension never downloads the core from a CDN.

## Files

| File | Purpose |
|---|---|
| `ffmpeg-core.js` | ES module glue generated by Emscripten |
| `ffmpeg-core.wasm` | FFmpeg and codec libraries compiled to WebAssembly |
| `ffmpeg-worker.js` | Worker written for this project |
| `ffmpeg-configure-flags.txt` | Configure flags used for the core |
| `source-versions.json` | Exact upstream source revisions |
| `source-versions.txt` | Human-readable copy of the source revisions |
| `SHA256SUMS` | Checksums for the two binary files |

  and <https://ffmpeg.aufzeichna.merginit.com/ffmpeg-lgpl/0.1.0/ffmpeg-core.wasm>

The configure flags include `--disable-gpl --disable-nonfree --disable-postproc`.
They do not include `--enable-gpl`, `--enable-libx264`, or `--enable-libx265`.
The core is therefore an LGPL build.

## Complete corresponding source

The complete corresponding source consists of the upstream archives listed
in [`source-versions.json`](source-versions.json), built with the flags in
[`ffmpeg-configure-flags.txt`](ffmpeg-configure-flags.txt) and the build
scripts in the provider repository:

- <https://github.com/merginit/ffmpeg.aufzeichna.merginit.com/blob/main/build/Dockerfile.lgpl>
- <https://github.com/merginit/ffmpeg.aufzeichna.merginit.com/blob/main/build/build-lgpl-core.sh>

If any upstream archive or build script becomes unavailable, open an issue
in this project's repository and the maintainers will provide the source.

## Replacing the core

The worker imports `ffmpeg-core.js` as an ES module and loads the adjacent
`ffmpeg-core.wasm`. A compatible replacement must keep the same
`createFFmpegCore` factory and the Emscripten virtual filesystem API. Replace
both files together and rebuild the extension if the replacement changes the
wasm URL.

`ffmpeg-core.js` and `ffmpeg-core.wasm` are unmodified upstream build
artifacts. The integration change is limited to `ffmpeg-worker.js`, which uses
an ES module import instead of `importScripts`.
